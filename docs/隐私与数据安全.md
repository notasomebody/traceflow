# 隐私与数据安全

## 本地优先原则

迹汇的核心功能在用户电脑上运行。SQLite 数据库、工作历史、报告和个人设置默认只保存在本机。程序不依赖中心业务服务器，也不默认启用遥测。

## 账号凭据

Jira、代码平台和业务平台的密码、令牌及会话信息应保存到 Windows 凭据管理器或 macOS 钥匙串。SQLite、日志、诊断包和配置分享码不得包含这些信息。

用户可以选择“仅本次使用”，让临时凭据在退出后清除。

## 工作内容

数据源默认采用最小必要采集：时间、事件类型、项目标识和变更摘要等元数据。源码、附件、网页正文和评论内容需要用户针对数据源主动授权。

敏感工作正文、报告和原始采集内容计划使用 AES-256-GCM 加密，密钥由操作系统凭据库保护。用于查询的日期、事件类型等非敏感索引字段可以保持可检索。

## AI 数据发送

本地模型模式不向外部发送数据。使用在线 AI 时，程序应在首次发送前展示发送预览，并允许用户：

- 排除源码、附件和完整网页
- 脱敏项目名、人员姓名和内部地址
- 按 AI 服务商设置允许字段
- 选择仅本次允许或保存规则

API 密钥同样进入操作系统凭据库。

## 本机使用统计

本机统计可以记录使用天数、报告生成次数、提交成功率、同步耗时和功能错误类型。统计不记录报告正文、源码或网页内容，也不自动上传。用户可以关闭统计、清空数据或导出 CSV。

## 配置分享码

普通分享码是可读取的离线配置，包含完整性校验但不提供保密性。密码分享码通过 PBKDF2-SHA256 派生密钥，并使用 AES-256-GCM 加密。

所有分享码自动排除：

- 姓名和个人工作历史
- 密码、令牌、Cookie 和浏览器会话
- 报告正文、源码和附件
- 本地数据库与日志

平台地址和项目映射可能仍属公司敏感信息。导出前应检查内容，只分享给可信人员。

## 日志与诊断包

错误日志只保存在本机，并应清理密码、令牌、Cookie、请求正文和内部地址。诊断包只能由用户主动生成；生成前应展示文件清单，并允许用户检查后再发送。

## 删除与退出

用户应能分别清除历史记录、统计数据、缓存、凭据和全部本地数据。删除操作应明确范围，并在执行前确认。

## 安全问题

发现漏洞时，请不要公开披露。请按照仓库根目录的 `SECURITY.md` 联系维护者。
